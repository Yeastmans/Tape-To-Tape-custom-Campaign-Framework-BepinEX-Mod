# Goalie GM offer presentation

The native GM prefabs have no wired event title and no detailed goalie stat fields. Their native skater condition row is a separate widget. Encoding goalie duration only in translatedButtonName therefore did not produce a contract preview in the visible GM card.

GoalieRecruitment now supplies EventChoice.FreeAgentLeavingConditions from the frozen offer contract: a detached reference-type MaxGamesCondition with the complete duration and zero played matches, or an empty list for a permanent offer. Native FreeAgentConditionsUI performs its usual localized row presentation. The preview does not add a native skater contract, mutate the frozen offer, increment progress, or save anything.

The existing managed MatchRuleRunner update calls GoalieGmPreview; there are no new native patches or compatibility metadata changes. It accepts only the actual visible current GM menu and exact valid goalie offer/candidate. The 13 authored fields are read directly, excluding Shot Power and including Pass Read in its native 0–1 fractional units. Skill is the authored skill field, not calculated Overall. The native GetBaseStat implementation falls back to skill for some enum values, so it is intentionally not used.

The four forward stat rows are hidden only for the owned goalie presentation. Their TMP label/value widgets provide native fonts; clones have no native stat or interpolation behavior and cannot receive raycasts. The exact LabelBar child is used when m_NameLabel is null, as it is in all three shipped GM variants. Twelve integer stats use two columns of six 20px rows within the existing Parchment stats area. The seventh row gives Pass Read the full width; signed Skill has a wider numeric box. Bounds are x63..374, y-211..-351, leaving six pixels before PlayerTalents at -357. Existing Overall, talents, names, contract row, and navigation remain untouched. Actual font glyph metrics informed the fractional/signed widths; source checks do not prove human readability.

Clones are created once per owned offer, reused across native selection refreshes, and hidden before deferred destruction. Closing, consuming, changing visit or replacing an item removes only the owned clones. Original visibility is restored only while the item still has the same candidate/details; a pooled item refreshed for another skater retains its new native visibility. An unknown layout logs once for that offer and creates no repeated objects.

Focused tests compile the actual presenter against native-shaped boundaries, including the shipped null m_NameLabel and LabelBar child. They cover all field values/units, stat-area bounds, numeric widths, hidden/closing/stale/consumed states, native refresh, pooled reuse, deferred destruction, unsupported geometry and steady-state allocation. Cecil diagnostics inspect the actual final runtime and installed interop: all named getters, native condition field/type, safe reference-type list payload, TMP-only instantiation, LabelBar lookup, and the existing managed tick call. Separate menu tests execute the actual extracted Choices body with finite, long-duration and permanent offers and verify preview conditions do not mutate their frozen policy.

Evidence is under artifacts/feature-test-crash-20261022/goalie-gm-preview, including native asset wiring, geometry, font metrics and native control-flow reports. Human GM-card readability, duration placement and navigation acceptance remain pending. No game process, campaign, save or installation was changed by this implementation task.
