# Native editor initialization hooks

Installed Il2CppInterop constructor resolution rejects ConstructorInfo.GetGenericArguments; managed fallback hooks do not intercept the game's direct native constructor calls. Play Now normalization and staged editor authority therefore use protected native menu initialization boundaries instead of TeamRosterData/CustomizeForwardData/CustomizeGoalieData constructor patches.

LineupMenu.InitData's successful-original postfix requires the exact input TeamData (direct or Metadata.Team) to match the newly initialized roster original, a distinct temporary team, matching native lock/home flags, a registered valid export and ready native bridge. Editable menus normalize absolute Line1/Line2; locked views retain the selected active line and its inactive line. Original team active-line state is retained.

The typed SkaterCustomizationMenu.Init(CustomizeSkaterData) postfix requires the exact resulting CurrentSkater/input owner before opening an accepted-revision session for forward or goalie. Repeated initialization of the same active staged edit retains confirmations. New staged/menu ownership supersedes old authority; stale callbacks and old-menu Hide cannot remove a newer session. Successful null or unrelated replacement retires the old menu owner defensively. Skipped originals or mismatching input cannot create authority. Original exceptions do not run Harmony postfixes; actual installed-provider diagnostics remain separate from direct managed boundary checks.

The source-linked native-style regressions construct data without constructor callbacks, reproduce both missing boundaries, and cover export/foreign input, activeLine2, locked/editable views, both editor roles, repeated and superseded ownership, stale Hide, explicit no-session save rejection and unchanged files. Existing goalie head/mask export/import/update checks now enter through the typed initialization boundary too. Final actual-interop/Harmony/native diagnostics and live editing acceptance remain required.
