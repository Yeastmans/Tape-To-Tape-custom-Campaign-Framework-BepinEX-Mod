# Native reward node reset and goalie completion

The real 1-0 overtime win on build 26150666 reached native campaign completion but left the goalie attempt Armed. The diagnostic replay showed the same run, controller, context, blueprint, team, goalie and token; only the current route coordinate had changed from the played node to (-1,-1). The launch ownership predicate consequently rejected completion and prevented the retention query from recording its result.

Native RewardsStep.ProcessAllRewards calls CampaignState.SetCurrentNode(null) before CampaignUpdateStep.Execute. The reviewed null branch clears currentNode and currentNodePoint, preserving lastNodePoint. Completion now observes that successful native call for a unique registered end-game context after proven play, and requires the exact campaign, blueprint, binding, live goalie and saved attempt. Only that context may finish against (-1,-1), with lastNodePoint still matching the original destination. Ordinary launch, handoff and live ownership checks remain strict. Native retention and exactly-once persistence remain required.

A successfully initialized replacement flow retires the previous context for the same controller/session. Its live team selection must be Rogue and any supplied context blueprint must match. Native Initialize leaves the context mode and blueprint at their defaults; UpdateEndOfGameContext fills them after the match, so default context values cannot be used as an initialization rejection rule.

The compatibility inventory adds the SetCurrentNode callback and protects the native reward flow constructor, end-game context population and rewards coroutine.
