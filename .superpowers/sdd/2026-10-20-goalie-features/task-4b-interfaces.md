# Task4b lifecycle and authority contract (before implementation)

The same V1 roster checkpoint gets an optional versioned immutable GoalieMatchAttempt context. It copies token, campaign/run/squad, home team stable ID, expected active goalie stable ID, originating roster revision/checkpoint, intended act/node type/index/layer, and prelaunch route witness. ArmedAttemptToken remains the compatibility authority and must equal the context token. ProcessedAttemptTokens is the run replay ledger. RecruitmentVisit is preserved. Only `Armed` is persisted here; neither launch nor setup certifies participation. Task4c completion clears token and context atomically.

The paired StartMatch/OnStartInput prefixes run before all native side effects. ShowMenu prefix retires previous preview lifetime; successful postfix opens a new generation. BackToMap, accepted OnCancelInput and OnDestroy invalidate pending reentry without interrupting save reconciliation. Exact immutable origin retains menu, generation, entry point/input object, campaign/run/home team/goalie/node native references and copied identifiers. IsShown, active hierarchy, exiting, zoom-test, mode, selected node and current ownership are checked again after save. A pending operation suppresses repeated clicks. No native exit flag or input block is set by the gate.

Roster.TryArmMatch reuses SaveChange and its exclusive mutation owner. The source snapshot is captured before native SetCurrentNode. Same-context retries reuse the existing token and save again; a confirmed local write plus platform failure remains saved but cannot authorize reentry. Unknown write invalidates roster editing and launch with Continue recovery. The separate changed-context/supersession policy is awaiting controller clarification and is not implemented until resolved.

Only the exact scoped SaveChange receipt with Durable true, matching admission/context/token, actual selected checkpoint and current roster checkpoint authorizes one wrapper reentry. The permit matches original method/menu/input and is consumed before original code executes; finally cleanup removes unused permits. The gate never consumes SaveRunData UniTask. Existing persistent MatchRuleRunner -> GoaliePersistenceBridge.Tick observes repository Task<bool>.

A LaunchOrigin object is emitted when the exact permit is consumed. It contains immutable attempt and exact launch ownership. Task4c must capture this event and pair it with the expected native node launch, controller home initialization and live home goalie; it may not query mutable current token to invent provenance. TryReuseOrigin(origin, campaign, homeTeam) validates that explicit originating object against the unconsumed saved token for rematch/restart. Continue rehydrates saved context and obtains a new launch origin only from the next gated preview. Reinitialization alone creates neither token nor authorization. No play/debit/completion is implemented in4b.

Native authority: completed canonical goalie-match-start-proof.md (26085704). New hooks: StartMatch, OnStartInput(UIInputShortcutBase), ShowMenu(MapNode) prefix/postfix, BackToMap, OnCancelInput(UIInputShortcutBase), OnDestroy. Manual contracts only; no HarmonyPatch attribute or partial startup activation. Final combined integration must resolve and activate persistence/fresh signing, both preview gates/lifetime hooks, source/live provenance, play and post-boss completion as a coherent set before feature enable. Existing profile remains off.

## Implemented partial API and remaining policy decision

Status: coherent candidate checkpoint, **not completed4b and not ready for independent review yet**. User/controller ruling remains pending for a saved, unconsumed attempt from a canceled/unlaunched preview when a different destination or goalie is selected. The mismatching-context branch contains an explicit TODO and withholds launch with a neutral unavailable message. This is a temporary incomplete boundary, not a chosen reject-until-restored product policy. No supersession, retirement, abandonment debit or inferred launch lifecycle has been implemented. Resume this decision before4b review.

Actual API:
- Core `GoalieMatchAttempt(GoalieRosterState,string homeTeamId,string routeWitness,int act,int nodeIndex,int layerIndex,string nodeType)` mints an attempt token, copying source revision/checkpoint and scope/goalie identity. All persisted properties have private setters. `Clone`, `Same`, `Matches`, `Validate` are pure. `Lifecycle == "Armed"` means intent only. Native destination type is exact `mapNode.GetIl2CppType().FullName`; coordinates are validation context, never replay identity. SourceRevision can be0 with empty SourceCheckpointId for a fresh unsaved run. The later durable roster checkpoint is the launch authorization checkpoint.
- `GoalieRosterState.Attempt` is optional DataMember14 in existing version1. Old checkpoints keep their prior shape; bare old ArmedAttemptToken without context cannot authorize launch. Validation pairs context with the exact token/scope. Current4a `CompleteMatch` now clears both token and context in its returned state; no completion caller is added here.
- `GoalieRosterRuntime.TryArmMatch(CampaignState,GoalieMatchAttempt,Action<ChangeResult>)` calls existing Stage/SaveChange. True means accepted, not durable. Existing exclusive changing owner serializes roster mutation, and Mutation.Complete additionally matches token/context. Recruitment ledger and contract records are retained. It presently supports first arming and exact same-context retry only; changed-context policy is pending.
- `GoalieMatchLaunchGate.Required` declares six named native method contracts (seven prefix/postfix patches); `Resolve()` resolves exact managed overloads/patches. There is deliberately no installer/startup invocation yet. The final combined installer must take this set together with4a signing/persistence and4c lifecycle/completion.
- `LaunchAuthorized : event Action<LaunchOrigin>` runs only when the exact single-use permit is consumed. Origin exposes immutable copied `Attempt`, original `Campaign`, `Run`, `HomeTeam`, `SourceGoalie`, `Menu`, `Input`, `Destination`, `PreviewGeneration`, `OriginEntry`, `CheckpointId`, `OperationId`, `Folder`. Native references are runtime provenance only and never persisted. Event observation itself does not prove that later native launch or play succeeded.
- `TryReuseOrigin(LaunchOrigin,CampaignState,TeamData)` requires the supplied originating object, original campaign/run/home ownership, saved unconsumed exact context, current native act/node coordinates, stable goalie/team IDs and available roster. It is a rematch/restart eligibility check **after native SetCurrentNode**, not permission to debit. `MatchesDestination(origin,campaign,mapNode,homeTeam)` adds exact original node reference, native type, act/index/layer validation after native selection. A4c prefix before SetCurrentNode may retain origin.Destination but must not claim this post-selection check already passed.

Task4c must subscribe before any activation. Capture one origin into an explicit node/controller/home initialization lineage; bind persistent goalie -> controller source clone -> live home goalie ID/ownership and retain that origin through play and successful CampaignUpdate completion. Native Goalies clone twice, so source/live pointer equality is insufficient. Use named native lifecycle callbacks from the completed proof; never attach whichever token happens to be current to a new GameManager. A direct node/scene start without a captured permitted origin is **unowned** and cannot certify participation/debit. This API does not claim preview hooks cover all indirect, debug or third-party paths. Rematch must follow its originating context and cannot mint identity on initialization. Continue returns to map and creates a fresh runtime origin only via a new durable gated preview click, while reusing the saved token where context matches.

The launch gate is not a platform retry loop. Native false/fault/cancel with reconciled local write preserves the attempt and waits for another human start activation; that start saves the same context and requires a new strict Durable receipt. Unknown persistence uses the existing roster-unavailable state and shows Continue recovery. Foreign receipts, mismatched token/admission/checkpoint and reused permits never authorize native start. The existing persistent bridge consumes the repository Task<bool>; this gate never awaits SaveRunData's native UniTask.

Final activation obligation: do not independently enable the fresh signing hook with absent launch/completion hooks, or enable only StartMatch and miss the inlined OnStartInput path. Resolve all required sets, verify pinned profile and ABIs, install them with rollback on any failure, register the4c consumer before native starts, then expose the feature as available. No profile was edited in4b.
