## Persisted identity and lifecycle

`GoalieMatchAttempt(GoalieRosterState,string homeTeamId,string routeWitness,int act,int nodeIndex,int layerIndex,string nodeType)` mints a token and copies campaign/run/squad, stable campaign-home team and expected goalie IDs, source roster revision/checkpoint, route witness and intended act/native type/index/layer before native SetCurrentNode. All persisted properties have private setters. Native pointers/timestamps/completion-generated IDs are not persisted. A fresh source may have revision0 and empty checkpoint; the resulting saved roster checkpoint is the launch authorization checkpoint. Coordinates validate context; only tokens provide replay identity.

`GoalieRosterState.Attempt` is optional DataMember14 in existing version1. It clones independently and validates matching token/scope. Older checkpoint shape remains readable; a bare ArmedAttemptToken without context cannot authorize launch. RecruitmentVisit and frozen contracts remain separate and unchanged. `ProcessedAttemptTokens` is the run replay authority and now includes **retired canceled tokens as well as completed tokens**; membership does not prove a contract charge.

Lifecycle values:
- `Armed`: saved launch intent, not proof that native startup or play occurred. An Armed record alone after process loss is ambiguous.
- `CanceledBeforeLaunch`: explicit observed native Cancel/BackToMap while the adapter still held runtime proof that this token had never been permitted to enter original startup. Cancellation is saved through the same coordinator. It is neither completion nor debit, and retains the token for same-context retry.

`Same` compares all identity/context fields and lifecycle; `SameIntent` compares identity/context excluding lifecycle. `CanceledBeforeLaunch()` and `Rearm()` return detached copies retaining token/context. Only the gate's owned runtime witness authorizes calling the cancellation mutation; Core copy helpers do not prove native cancellation. CompleteMatch rejects an unconsumed CanceledBeforeLaunch attempt, clears both ArmedAttemptToken and Attempt on accepted completion, and still returns a detached no-op for any already processed token before other authority checks.

## Save mutation API

`GoalieRosterRuntime.TryArmMatch(CampaignState,GoalieMatchAttempt,Action<ChangeResult>)` accepts an Armed proposal and uses existing Stage/SaveChange. It permits first arming, exact same intent retry, and replacement of a saved CanceledBeforeLaunch context. On replacement it appends the canceled token to ProcessedAttemptTokens and saves the new token/context in the same checkpoint without touching either goalie's progress. Same-context retry rearms the same token. True means accepted, never saved success.

`TryCancelMatch(CampaignState,GoalieMatchAttempt expected,Action<ChangeResult>)` requires the exact current Armed context and caller-owned observed never-permitted cancellation provenance. It uses the same save coordinator to publish/save CanceledBeforeLaunch, without token retirement or debit. Do not call it based on an arbitrary recovered Armed record. Mutation.Complete matches exact token/context. Existing SaveChange exclusive owner, scoped caller/repository/run receipt, three persistence outcomes, admission/completion reentry, and recruitment ledger preservation remain intact.

Native Cancel remains usable before save completion. The gate records CancelRequested and invalidates that preview immediately. If the launch save is pending, its completion first reconciles the actually saved state, then schedules cancellation through the same coordinator. While cancellation saves, replacement input waits and never autolaunches the old/new preview. Local confirmed cancellation or replacement plus native false/fault/cancel remains saved. A replacement still needs a fresh strict Durable receipt to launch. Proven no-write rolls back cancellation/replacement, including old-token retirement. Unknown readback makes editing/launch unavailable and explains Continue recovery. An unwritten cancellation can be retried on the next Start activation; unresolved state is never guessed.

## Provenance limit and final integration

A durable CanceledBeforeLaunch record survives Continue and can be replaced at a changed destination or goalie. Once a startup permit is committed, its never-launched witness is removed. Later reopening/canceling a preview cannot relabel that token as unlaunched. After process loss, a recovered Armed token also cannot prove that it never started; it permits same-context retry, but changed-context launch displays: "This saved match may already have started. Resume its original match and goalie; a changed attempt cannot be verified." No cancellation or abandonment debit is inferred. The controller explicitly accepted this conservative provenance boundary under the scoped user ruling.

Final integration must atomically resolve/verify/install reviewed signing/persistence, both start gates/lifetime observations,4c source/live ownership/play/post-boss completion and its origin consumer, rolling back partial installation. Never enable fresh signing without complete launch/completion support, or StartMatch without OnStartInput. Final native audit and human validation must cover actual Cancel/save ordering, UI recovery, native wrapper reentry, Continue/rematch, live goalie binding and completion. No profile/installation/gameplay validation was performed by4b.
