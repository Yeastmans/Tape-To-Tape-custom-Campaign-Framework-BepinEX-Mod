Successful native Boss/Challenge/Elite LaunchMatch finalization must pass 4b MatchesDestination (including its private committed-permission registry) after SetCurrentNode. - Successful original normal OnFaceoff/OnPuckDropLaunch or Shootout.InRoundState.OnEnter freezes one participant. Failed/skipped callbacks do not count. A foreign skip, missing callback, repeated/conflicting phase, exception or incomplete definition source is unknown.
- Successful whole CampaignUpdateStep native execution, no exception and `UniTask.Status == Succeeded` are required after native earned-state copy, boss bonuses and bench/run bookkeeping. ## Save and failure interface

`GoalieRosterRuntime.TryCompleteMatch(CampaignState, GoalieMatchAttempt, string participant, bool prevented, Action<ChangeResult>)` is a separate completion admission boundary. It preserves CanEdit's existing between-match UI restriction, rejects changed run/squad/team/attempt, and consumes token, participant debit, reconciliation and full native state in the same proposed checkpoint. True means accepted async work, never saved success. The caller must hold the proven originating completion; this API does not manufacture provenance.

`ChangeResult` and SaveReceipt are unchanged. Committed with Durable=false means exact local pair reconciled while actual native/platform result failed. Rejected/no-write rolls back the exact completion mutation; unknown persistence retains existing recovery semantics. Any failed completion requires Continue recovery via `CompletionUnavailable`, conditional on the exact still-owned originating attempt. It cannot lock a newer attempt from an old callback. The following preview/menu sees the existing UnavailableReason. Native results/exceptions remain untouched, and CampaignSaveStep's fire-and-forget return is never proof of saving.

No persistent schema, recruitment-visit ledger, Core duration policy, cancellation retirement semantics or promise implementation changed. ProcessedAttemptTokens is never used as proof of a played charge. Recovered Armed state alone still cannot establish past play; the 4b process-loss ambiguity rule remains in force. Existing 4a default/custom/off/frozen-duration and deferred-signing behavior is reused.
