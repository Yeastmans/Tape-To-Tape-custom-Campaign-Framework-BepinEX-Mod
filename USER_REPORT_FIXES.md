# Beta 1.0 revision 3 - user report update

Release label explicitly approved by the user. The changes below have technical validation; native gameplay confirmation remains pending. Squad pool choices are implemented: Use own pools is off by default (shared), and enabling it provides separate bench, superstar and free-agent selections. Own pools start empty and preserve selections when turned off.

## Confirmed causes and local changes

### Unavailable export selections follow-up

The glasses error came from looking up the literal `none` in the asset catalog; only helmets had an exception. Exports also aborted on any unknown appearance or reward ID. `none` is now accepted for no equipment, and unavailable appearance/equipment, talents, abilities and relics are omitted only from the exported copy. Valid entries in mixed lists, cross-role IDs, home/away styles and level-2 relic aliases remain intact. Missing logo files are omitted too; corrupt embedded PNGs still fail validation.

Filtering happens after appearance inheritance and before writing both native models and sidecars, so copied settings cannot restore unavailable values. Library export snapshots receive the same filtered settings. The export success dialog lists each skipped selection and affected player/team. Authored files are unchanged. The exporter refreshes data from the selected content folder rather than switching catalogs to the runtime override destination.

Validation: 38 new tolerant-export checks, 31 existing export checks and 14 Cheese export checks pass (83 total). The new checks invoke the built Studio's actual standalone skater, goalie and whole-team export entry points with an isolated game-save destination; produced override files are archived and removed by their returned unique IDs. Native gameplay and appearance are still pending human confirmation. Evidence: `artifacts/export-skip-20261014`.

4. Export a copy with an incomplete roster or invalid numeric stat. It must still explain the structural error and publish no partial team. Restore those values and retry; the success report must contain only the current export's omissions.

These changes remain pending until Save opponent/Save player team. Start active follows each skater when changing positions on Line 1. Goalies and empty positions reserved for squad setup remain protected. The previously published roster-saving and Act 3 continuation repairs remain included.

### Roster saving and Act 3 continuation follow-up

The follow-up release includes both repairs approved by the user. Other unfinished reward-editor changes are excluded from its source and build.

- **Roster save:** A player without an explicit Position field appeared in the slot inferred from its filename, but saving the player defaulted that missing field to Center. The roster then treated duplicate Centers as Line 2 players. Player saving now retains the displayed roster assignment, including legacy filenames and nested roster folders.
- **Line recovery:** Each skater card offers Move to Line 1/2 for the matching empty position, or Swap with Line 1/2 when occupied. Changes are pending until the team is saved. Existing Line 2 players remain accessible when two-line authoring is off. Setup-reserved empty slots and goalie roles remain protected. A failed swap write restores the other player instead of leaving a half-written swap.
- **Game loading:** Explicit saved positions now take precedence over position-based filenames, using the same position reader as Studio. Legacy filenames remain a fallback and nested roster files are loaded.
- **Act 3 to later authored maps:** The native game reset the run at its Act 3 boundary before the mod generated the next authored map. The continuation patch selects the next authored act before that reset branch, retaining the current run, squad and roster. Final campaign completion, failed/conceded runs and base-game mode are excluded. This prevents the reset; it does not recover a roster already lost in an older save.

Release-source checks: 35 roster save/move checks, 26 roster creation/removal checks, 122 squad editor/validation checks, 38 managed transition checks and 87 source-linked completion checks passed. Roster layouts were inspected at 960 x 620 and 1320 x 860. These are technical checks; native gameplay and the reporting user's retest remain pending.
