# Beta 1.0 revision 3 - user report update

Release label explicitly approved by the user. The changes below have technical validation; native gameplay confirmation remains pending. Squad pool choices are implemented: Use own pools is off by default (shared), and enabling it provides separate bench, superstar and free-agent selections. Own pools start empty and preserve selections when turned off.

## Confirmed causes and local changes

| Report | Cause | Local change |
| --- | --- | --- |
| McShaggy in an empty starter slot | Cloned squad templates retained donor players. Old cleanup skipped all-empty rosters and could rename a donor to Draft Pick instead of removing it. Native construction also accepted fills into unconfigured positions. | Remove unselected donor forwards, reserves and goalie from detached custom templates. Bind lead mechanics to an existing selected starter without moving it. During native new-run construction, accept only the captured selected source IDs, including explicitly benched starters. Save loading and subsequent lineup edits remain authoritative. Unmodified complete native squad copies retain their selected native roster. |
| Editing Joan Ozark fails with duplicate-name error | Campaign-wide uniqueness checking treated an existing roster copy as a new name. | Unchanged existing names, including casing changes, can save. New/imported same-name copies receive the next available numeric suffix (2, 3, etc.) across the destination campaign or local collection. Explicit renames still validate collisions. |
| Play Now export rejects import-only players | Export rejected every Import Player marker without resolving the reference. | Resolve fixed native references from the captured base-player catalog, overlay authored fields, and export a complete snapshot. Complete legacy snapshots can export without the original catalog entry. Missing/ambiguous incomplete references and RANDOM still fail with an actionable message. |
| Individual kit colors unavailable | Player palette migration deliberately removed all kit colors; the picker exposed only team colors and premade styles. | Explicit per-piece home/away opt-ins preserve custom kit colors through migration, editor save/reopen, preview, export sidecars and runtime palette application. Team/Custom/Premade are available for colorable kit pieces. Native stick/skates (goalie stick/blocker) remain a shared personal palette for both kits. |
| More than two nodes unavailable | Studio enforced a two-node authoring cap. | Remove the practical count cap, pack three or more authored rows closer, expand the editor canvas to keep cards usable, and use compact preview markers. Runtime still fits actual artwork and may stagger tall arenas horizontally. |

## Manual validation on the eventual published build

Use a disposable campaign copy, keep the original campaign and saved run, and confirm the installed build ID matches the eventual revision 3 manifest. Do not perform these checks on revision 2 and attribute the results to this update.

1. **Empty starter slots:** Create a custom squad with one named Center and an explicitly selected goalie, leaving other skater slots empty. Start a new run. The squad preview and starting roster must contain only selected players until you choose more. No McShaggy, Draft Pick or renamed donor may appear. Repeat with no authored skaters and with an authored player set to start on the bench. Explicit superstar/bench choices must still join correctly and authored positions must remain unchanged. Also inspect an unassigned goalie slot: no donor goalie should appear. If the native flow cannot proceed without required choices, record that outcome rather than calling it a successful run.
2. **Saved roster:** Resume a copy of an existing save where a drafted player replaced an authored starter. The saved player and position must remain intact. Change the lineup after starting and confirm the new-run guard does not lock later edits.
3. **Existing player save:** Import the same player into two different teams, open either copy, change a stat without changing its name, save and reopen. Only that copy changes and no duplicate-name error appears. Import another copy twice: expect Joan Ozark 2 and Joan Ozark 3 (or the next free suffix), with original files intact. Repeat in the player library, roster, bench, superstar and free-agent pools, including a same-name batch. Explicitly renaming a different existing player to an occupied name still shows the collision message.
4. **Legacy Play Now export:** Use a six-position team containing fixed Import Player references and a refreshed game-art catalog. Export it, open Play Now, and verify names, heads, stats and goalie. Repeat after changing one player's stat and colors. A missing reference or RANDOM should stop before writing a partial package and explain what needs resolving.
5. **Personal colors:** For a skater and goalie, turn Team equipment off. Choose Custom jersey colors: cyan home and orange away, including distinct secondary and accent channels. Set another piece to Team and one to Premade. Save/reopen; inspect front/back, sleeves, numbers, gloves/catcher, pants and socks/pads. Launch home and away matches and export to Play Now. Only the selected player's custom pieces should change; teammates keep team colors and premade artwork remains intact. Switch only the home jersey to Team and confirm away remains custom. Personal color opt-ins are independent of the global style toggle; choose Team for each piece to restore team colors.
6. **Three choices:** Build a connected three-node layer, save/reopen, use undo/redo, then start a fresh campaign run. All three nodes must remain selectable and all outgoing routes must work. Inspect a layer containing Coach/Rest/Shop and another containing large match arenas and reward badges. The compact authoring coordinates must not hide nodes, overlap selectable targets, lose labels, expose missing background or break links. Repeat with four choices and a larger layer; record horizontal staggering where needed to fit full artwork.
7. **Squad pools:** Open two custom squads and their Player pools tabs. Use own pools must be unchecked initially. Enable it for squad A: all three pools start empty. Import distinct players into its Bench, Superstars and Free agents; save, reopen and verify all selections. Give squad B different choices. Start a fresh run with each squad and verify only its selected bench, stars and GM recruits appear. Leave an own pool empty and verify its starting screen is skipped or GM offers no recruits, with no native substitute. Turn Use own pools off and verify shared choices return; enable it again and verify the stored choices return. Uncheck a free agent, save and confirm its editable copy remains but is never offered. Resume a saved run and verify the saved squad selects the correct recruitment pool while signed players retain their progress. Explicitly select McShaggy once to confirm he remains available when chosen. Repeat the empty-roster check without him selected.
